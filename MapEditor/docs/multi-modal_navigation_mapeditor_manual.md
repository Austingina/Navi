# 操作手册：用 MapEditor 制作场景地图与带语义点位、传送门的多 Submap SLAM 地图

本手册以「从 SLAM 点云出发，制作一张可供 NaviAgent 使用的多子地图（multi-submap）地图」为核心目标，
覆盖 **子地图组织 → 坐标对齐 → 语义点位 → 传送门 → 路线 → 保存 / 导出** 的完整流程；
并进一步介绍 MapEditor 的 **分层场景地图**能力 —— 把多张 SLAM 地图用经纬度锚定到一张 OSM 底图上，
组成一个可跨地图导航的 **场景（Scene）**，覆盖 **导入 OSM 底图 → 叠加对齐 SLAM 地图 → 场景语义点位 / 区域
→ 场景传送门 → 跨地图全局路线 → 保存 / 打开场景** 的完整流程。逐一解释其中的关键概念。

## 1. 先理解关键概念

在动手前，先建立下面这几个概念的心智模型，后续每一步都会用到。

### 1.0 分层地图模型（Scene → SLAM 地图 → Submap）总览

MapEditor 采用**三层**地图模型，自上而下、逐层嵌套：

```
场景 Scene（WGS84 / OSM 底图，经纬度主干）
 └── SLAM 地图 A（geo_anchor 锚定到 OSM）      ← 一个「地图工程 / MapProject」
 │     ├── submap: floor（TF 树根 = default_submap）
 │     └── submap: underground（parent = floor）
 └── SLAM 地图 B（geo_anchor 锚定到 OSM）
       └── submap: ...
```

- **场景（Scene）**：最外层容器，以 **OSM 底图**（经纬度 WGS84）为基准，把多张 SLAM 地图摆到真实地理位置上；
  还承载 **场景语义点位 / 区域**、**场景传送门**、**跨地图全局路线**。持久化为一个 **`scene.json` + 目录**。
- **SLAM 地图**：一张独立的多子地图工程（即本手册 §1.1 的「地图工程」），带一个 **`geo_anchor`**
  说明它的原点落在 OSM 底图的哪个经纬度、朝向与缩放。
- **Submap（子地图）**：SLAM 地图内部的最小可加载单元（楼层 / 区域），彼此用 TF 树组织。

界面上对应左侧两个 Tab：

- 「**场景地图**」Tab —— 编辑最外两层（OSM 底图、各 SLAM 地图的摆放、场景点位/区域/传送门、全局路线）。
- 「**SLAM地图**」Tab —— 编辑**当前激活**的那张 SLAM 地图的内部（子地图、语义点位、传送门、内部路线）。

> §1.1–§1.7 讲的是**单张 SLAM 地图**内部（Submap 层）的概念；§1.8 起讲**场景层**的新概念。
> 如果你只做单张地图，看完 §1.1–§1.7 + §4 即可；要做跨地图场景，再看 §1.8 起 + §5。

### 1.1 地图工程（Map Project）与工程目录

一张完整的 SLAM 地图在 MapEditor 中对应一个 **地图工程（MapProject）**，以**文件夹**为读写单位：

- 主配置文件名 = **`<目录名>.json`**。例如目录 `maps/building_a/`，则配置为 `maps/building_a/building_a.json`。
- 各子地图的点云 `.pcd` 也存放在该目录下，`map_file` 用**相对路径**引用。
- `global.default_submap` 指定全局参考子地图；**未设置有效值时无法正常保存 / 被运行时正确加载**。

> 这个「目录 + 同名 JSON + 若干 PCD」的结构，正是运行时 `NaviAgent/MapManager` 读取的
> `multifloor.json` 风格地图（见 `submap_system.md` §2）。

### 1.2 子地图（Submap）

**子地图**是地图的最小可加载单元，通常对应一个楼层 / 一个区域 / 一次连续 SLAM 建图的结果。
一张地图由多个子地图组成，每个子地图有：

| 属性 | 含义 |
|------|------|
| `id` | 唯一标识（英文/数字，建议如 `floor`、`underground`、`5floor`） |
| `name` / `description` | 人类可读名称与描述 |
| `map_file` | 该子地图的点云文件（相对工程目录） |
| `transform` | 该子地图**本地坐标系 → 父子地图坐标系**的刚体变换 |
| `parent_submap` | 父子地图 id（为空表示它是 TF 树的**根**，即 `default_submap`） |
| `semantic_points` | 该子地图内的语义点位 |
| `submap_portals` | 从该子地图通往其它子地图的传送门 |

### 1.3 TF 树、`transform` 与 `default_submap`

多个子地图通过 **父子关系** 组成一棵 **TF 树**：

```
        floor  (根 = default_submap, transform = 单位阵)
        ├── underground   (parent_submap = floor)
        └── 5floor        (parent_submap = floor)
```

- 每个子地图的 `transform` 表示 **本地坐标 → 父坐标** 的变换。
- 根节点（`default_submap`）没有父节点，其 `transform` 为单位阵，它的坐标系即**全局坐标系**。
- 任意子地图局部点到全局的变换 = 沿 TF 树逐级向上级联（`submapToRootMatrix`）：

$$
T_{sub \to root} = T_{parent \to root}\cdot T_{sub \to parent}
$$

- **只有 TF 树的根节点才能被设为 `default_submap`**（编辑器会强制校验）。

> 为什么重要：语义点、传送门、路线折线在 3D 视图中的世界位置，都是用 `submapToRootMatrix`
> 把子地图局部坐标换算到全局后绘制的。对齐没做对，点位就会“飘”。

### 1.4 语义点位（Semantic Point）

**语义点位**是子地图内一个**命名的导航目标 / 关键位姿**，坐标是该子地图的**局部坐标**。

- 每个点位有 `type`（类型）与一个或多个位姿（position + orientation 四元数）。
- 支持的类型（编辑器右侧属性栏下拉可选）：
  `single_pose`、`multi_pose`、`LowPrecision_pose`、`elevator_call`、`elevator_wait`、
  `elevator_in`、`elevator_out`、`door_open`。
  - `single_pose`：单个目标位姿（最常用）。
  - `multi_pose`：一串**按顺序经过**的位姿（如出入口、闸机的“进/出方向”）。
  - `elevator_*` / `door_open`：电梯 / 门等特殊语义，供上层决策使用。
- `need_inspect`（是否需要巡检）：`single_pose` 默认 `true`，其它类型默认 `false`，可手动改。

### 1.5 传送门（Portal）

**传送门**是**两个子地图之间的连接点**，用于跨子地图（跨楼层）导航时“切图”。

- 传送门由 `portal`（一个**语义点位名**，即传送点的物理位置）+ `submap`（**目标子地图 id**）组成。
- **传送门是单向的**：`floor → underground` 与 `underground → floor` 需要**分别定义**。
- 实践上应把传送门设在两个子地图**物理重叠**的位置（电梯口、楼梯口、坡道口），
  且传送门关联的语义点位坐标要反映真实物理位置。

### 1.6 路线（Route）

**路线**是一串有序途经点（waypoint），可跨子地图：

- 每个 waypoint 引用 `{submap, semantic_point}`（某子地图里的某个语义点）。
- 也可**嵌套引用另一条路线**（`route` 字段），实现路线复用。
- `default_route` 指定默认路线。

### 1.7 版本号与构建号

- `version`：语义版本号，默认 `1.0`，由你在「文件 → 修改版本号」中手动维护。
- `build_no`：**每次保存**时自动写为 `YYYYMMDDHHMMSS`，供下游比对“是否有新版本”，无需手填。

### 1.8 场景（Scene）与 OSM 底图

**场景**是承载多张 SLAM 地图的最外层容器，以 **OSM 底图**（OpenStreetMap，经纬度 WGS84）为地理主干。

- 支持导入 **`.osm`（XML）** 或 **`.osm.pbf`（二进制）** 底图；导入后主视图以俯视图渲染道路 / 建筑 / 水体等。
- 场景有一个 **原点（origin）**：经纬度换算的本地 ENU 基准，未显式设置时取 OSM 底图边界中心。
- 场景整体持久化为一个 **`scene.json`**，配套一个**目录**（OSM 与各 SLAM 地图的 PCD 都复制进目录，
  JSON 内一律用**相对路径**引用，便于整目录迁移）。详见 §5。

### 1.9 `geo_anchor`：把 SLAM 地图锚定到 OSM

每张 SLAM 地图在场景里都有一个 **`geo_anchor`**，描述它的**原点**落在 OSM 底图上的位置与姿态：

| 字段 | 含义 |
|------|------|
| `origin.lon` / `origin.lat` / `origin.alt` | SLAM 地图原点对应的经纬度 / 海拔 |
| `heading_deg` | X 轴相对正北的朝向角（度） |
| `scale` | 缩放（通常为 1；用于弥补尺度差异） |

在「场景地图」Tab 里，SLAM 地图以**正交投影足迹**叠加在 OSM 底图上，可用鼠标**拖拽 / 旋转 / 缩放**
把它对齐到底图上的真实位置，实时写回 `geo_anchor`（见 §5）。

- **锁定（locked）**：确认某张地图对齐无误后，可在属性栏点「🔒 锁定对齐结果」。锁定后该地图不能被单独拖动
  （拖它等于平移整个视图），且经纬度/朝向编辑框只读，避免误操作破坏成果；解锁后可继续微调。
- **撤销**：拖拽对齐时按 **Ctrl+Z** 可逐步回退到上一步的拖动结果。

### 1.10 场景语义点位（Scene Semantic Point）与区域（Area）

与 SLAM 地图内部的语义点位（§1.4，用**局部坐标**）不同，**场景语义点位**直接标注在 **OSM 底图**上，
用**经纬度 + 航向角**表示，用于在“地理尺度”上定义关键位置（园区出入口、广场、路口等）：

| 字段 | 含义 |
|------|------|
| `lon` / `lat` / `alt` | 经纬度 / 海拔 |
| `heading_deg` | 航向角：与正北的夹角，顺时针为正（0=正北，90=正东） |
| `type` | 类型，与 SLAM 语义点位一致（默认 `single_pose`） |
| `need_inspect` | 是否需要巡检（默认 `false`） |
| `area` | 所属**区域**名（空=未归属） |

- **区域（Area）**：对场景语义点位做**分组聚合管理**（如「智城」「彩虹」两个园区），仅用于组织，不影响坐标。
- 位置既可在底图上**点选**确定，也可在右侧属性栏**精细调整**经纬度与航向角。

### 1.11 场景传送门（Scene Portal）

**场景传送门**把一个**场景语义点位**定义为**某张 SLAM 地图的入口**，即“从园区地理层进入某栋楼的 SLAM 地图”。

- 与 SLAM 地图内部传送门（§1.5）一致：**以语义点位为标识，无需单独命名**。
- 由 `场景语义点位名` + `target_slam_map`（目标 SLAM 地图 id）组成，面板上显示为「点位名 → 目标地图」。

### 1.12 跨地图全局路线（Global Route）

**全局路线**是可**跨多张 SLAM 地图 / OSM 底图**的一串有序途经点，在「场景地图」Tab 下管理
（区别于 §1.6 的“内部路线”——后者属于单张 SLAM 地图，随其激活时显示在「SLAM地图」Tab）。

全局路线的途经点是**异构**的，可为下列任意一种：

| 途经点类型 | JSON 形态 | 说明 |
|-----------|-----------|------|
| 场景语义点位 | `{"scene_point": "名称"}` | 引用 OSM 底图上的场景语义点位 |
| 地图内点位 | `{"slam_map": "...", "submap": "...", "semantic_point": "..."}` | 引用某 SLAM 地图某子地图的语义点 |
| **内部路线段** | `{"slam_map": "...", "route": "..."}` | 把某 SLAM 地图的一条内部路线整体作为一段 |
| GPS 点 | `{"lon": ..., "lat": ...}` | 经纬度点 |
| 指令 | `{"instruction": "..."}` | 文本指令 |

- 可把「场景语义点位」**拖拽**到某条全局路线上加入途经点；
- 也可把「SLAM地图」Tab 里的**内部路线**拖到「场景地图」标签上（悬停自动切 Tab），再落到某条全局路线的
  指定位置，作为该全局路线的一段（详见 §5）。

### 1.13 SLAM 地图的「全名」与「code」

在「场景地图」Tab 右键某张 SLAM 地图可**重命名**，包含两个字段：

- **全名（name）**：人类可读名称（如「彩虹科技大厦」）。
- **code（id）**：地图的**唯一标识**，即树节点名与 JSON `slam_maps` 的键；全局路线 / 传送门都以 code 引用。
  修改 code 时，编辑器会自动同步更新所有引用它的全局路线途经点与场景传送门。

### 1.14 场景构建号（scene.build_no）

- 顶层 `scene.build_no` 与 SLAM 地图的 `global.build_no` **同格式**（`YYYYMMDDHHMMSS`）。
- **仅当内容有变化时**才在保存时刷新时间戳：场景内容（含任一 SLAM 地图内部信息）有更新才更新 `scene.build_no`；
  各 SLAM 地图的 `global.build_no` 也遵循“**其内部信息有更新才刷新**，否则保持不变”。

## 2. 产物长什么样（目标 JSON 结构）

有两种产物，取决于你做的是**单张 SLAM 地图**还是**场景**：

- **单张 SLAM 地图工程**：目录 + `<目录名>.json`（`multifloor.json` 风格），见 §2.1；运行时直接消费此格式。
- **场景**：目录 + `scene.json`（内联多张 SLAM 地图 + OSM + 全局路线），见 §2.2。

### 2.1 单张 SLAM 地图工程 JSON（`<目录名>.json`）

制作完成后，工程目录里的 `<目录名>.json` 结构如下（这也是运行时消费的格式）。
先看一眼目标，制作过程会更有方向感：

```json
{
  "global": {
    "default_submap": "floor",
    "default_route": "线路A",
    "version": "1.0",
    "build_no": 20260720101500
  },
  "submaps": {
    "floor": {
      "name": "地面层",
      "description": "Ground floor / 1F",
      "map_file": "floor.pcd",
      "transform": {
        "translation": {"x": 0.0, "y": 0.0, "z": 0.0},
        "rotation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0}
      },
      "submap_portals": [
        {"portal": "电梯口", "submap": "underground"}
      ],
      "semantic_points": {
        "北面车库": {
          "type": "single_pose",
          "pose": {
            "position": {"x": -50.2, "y": -4.9, "z": 0.0},
            "orientation": {"x": 0.0, "y": 0.0, "z": 0.7071, "w": 0.7071}
          },
          "need_inspect": true
        },
        "电梯口": {
          "type": "single_pose",
          "pose": { "position": {"x": -2.0, "y": 3.0, "z": 0.0},
                    "orientation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0} },
          "need_inspect": false
        }
      }
    },
    "underground": {
      "name": "地下层",
      "map_file": "underground.pcd",
      "parent_submap": "floor",
      "transform": {
        "translation": {"x": -47.5, "y": -8.4, "z": 0.0},
        "rotation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0}
      },
      "submap_portals": [
        {"portal": "电梯口", "submap": "floor"}
      ],
      "semantic_points": {
        "电梯口": { "type": "single_pose",
          "pose": { "position": {"x": 0.0, "y": 0.0, "z": 0.0},
                    "orientation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0} },
          "need_inspect": false }
      }
    }
  },
  "routes": {
    "线路A": {
      "description": "从地面层经地下层巡检",
      "waypoints": [
        {"submap": "floor", "semantic_point": "北面车库"},
        {"submap": "underground", "semantic_point": "电梯口"}
      ]
    }
  }
}
```

字段与概念的对应关系已在 §1 说明。`multi_pose` 类型的点位用 `poses`（数组）代替 `pose`；
嵌套路线的 waypoint 形如 `{"route": "线路A"}`。

### 2.2 场景 JSON（`scene.json`）

场景把 OSM 底图、多张 SLAM 地图（**内联**其完整工程内容）与跨地图全局路线保存到一个 `scene.json`：

```json
{
  "scene": {
    "name": "西丽园区",
    "crs": "WGS84",
    "build_no": 20260721204312,
    "origin": { "lon": 114.0165988, "lat": 22.6373916 },
    "osm": {
      "source": "osm/xili_5km_merged.osm.pbf",
      "bounds": { "min": {"lon": 113.7475, "lat": 22.4964},
                  "max": {"lon": 114.2856, "lat": 22.7783} }
    },
    "semantic_point_areas": ["智城", "彩虹"],
    "semantic_points": {
      "彩虹南门": { "type": "single_pose", "area": "彩虹", "need_inspect": false,
                   "lon": 113.9358, "lat": 22.5573, "alt": 0, "heading_deg": 0 }
    },
    "portals": {
      "彩虹南门": { "target_slam_map": "caihong" }
    }
  },
  "slam_maps": {
    "caihong": {
      "name": "彩虹科技大厦",
      "pcd_base": "caihong",
      "ortho_visible": true,
      "locked": true,
      "geo_anchor": {
        "origin": { "lon": 113.9360, "lat": 22.5581, "alt": 0 },
        "heading_deg": -90, "scale": 1
      },
      "global":  { "default_submap": "2f", "default_route": "route262",
                   "version": "1.0.1", "build_no": 20260717160629 },
      "submaps": { "...": "（与 §2.1 单图工程内的 submaps 结构完全一致）" },
      "routes":  { "...": "（该 SLAM 地图的内部路线）" }
    }
  },
  "routes": {
    "智城AB栋巡检": {
      "description": "",
      "waypoints": [
        {"scene_point": "智城西北角"},
        {"scene_point": "智城仙茶路北出口"},
        {"slam_map": "caihong", "route": "1f_eh"},
        {"slam_map": "zhichengA2A3", "submap": "1f", "semantic_point": "北门"}
      ]
    }
  }
}
```

- `scene`：底图与场景级信息（原点、OSM 引用与边界、场景语义点位/区域、场景传送门、`build_no`）。
- `slam_maps`：以 **code(id)** 为键，每张内联其 `geo_anchor` + 完整工程（`global`/`submaps`/`routes`）
  以及场景级附加项 `name`/`pcd_base`/`ortho_visible`/`locked`。
- `routes`：**顶层的跨地图全局路线**（其途经点类型见 §1.12）。

## 4. 完整制作流程（分步）

下面以「制作一张含 `floor`（根）+ `underground` 两个子地图」的地图为例。三个及以上子地图同理扩展。

### 步骤 0：规划

先在纸面上确定：

- 各子地图 `id`（英文，稳定不改）与哪一张作**根 / 默认子地图**（`default_submap`，一般是主楼层）。
- 各子地图之间的**物理重叠点**（未来的传送门位置，如电梯口）。
- 需要的关键语义点位与巡检路线。

### 步骤 1：建立工程并载入第一张子地图（根）

编辑器需要一个**已激活的地图工程**作为编辑对象。选择下面任一种方式载入根子地图：

- **A. 已有地图目录**（推荐，若 SLAM 产物已是「目录 + `<目录名>.json`」结构）：
  菜单 **文件 → 导入单张地图目录 (multifloor.json)…**，选择该目录。它会成为当前激活地图。

- **B. 从零起步（仅有裸 `.pcd`）**：先做一次性“种子”目录 —— 新建文件夹（如 `building_a/`），
  把根子地图点云放进去（如 `floor.pcd`），并在其中放一个最小的 `building_a.json`：

  ```json
  {
    "global": { "default_submap": "floor" },
    "submaps": {
      "floor": {
        "name": "地面层",
        "map_file": "floor.pcd",
        "transform": { "translation": {"x":0.0,"y":0.0,"z":0.0},
                       "rotation": {"x":0.0,"y":0.0,"z":0.0,"w":1.0} },
        "submap_portals": [],
        "semantic_points": {}
      }
    },
    "routes": {}
  }
  ```

  然后同样用 **文件 → 导入单张地图目录** 打开它。此后所有编辑都在 GUI 完成。
  （若你的 SLAM 流程能直接产出上述结构，可跳过手写这步。）

载入后编辑器会自动切到「SLAM地图」Tab，3D 视图显示根子地图点云。

### 步骤 2：确认默认子地图（根节点）

在「SLAM地图」Tab 的子地图树中，右键根子地图（如 `floor`）→ **⭐ 设为默认地图**（即 `default_submap`）。
名称旁出现 ⭐ 即表示它是 `default_submap` / TF 树根，`transform` 保持单位阵。

> 只有**无父节点**的子地图才能设为默认子地图。

### 步骤 3：加入其余子地图

对每一个附加子地图（如 `underground`）：

1. 菜单 **编辑 → 新增 Submap…**（或工具栏 `+ Submap`、面板 `+ 新增 Submap`）。
2. 在对话框中填写 **id**（如 `underground`）、名称、描述，并**导入其 `.pcd`**（可选同时导入其 JSON）。
3. 确定后，该子地图出现在树中，点云叠加显示在 3D 视图（初始 `transform` 为单位阵，通常会与根图重叠/错位，下一步对齐）。

### 步骤 4：把子地图对齐到根坐标系，并建立父子关系

目的：让每个子地图的点云在**同一个全局坐标系**里对上真实相对位置，并写入其 `transform`。

有三种方式（详细参数见 `README.md` §6），按数据情况任选：

- **方式一 / 二：3D-BBS 点云匹配**（推荐，自动求解 `transform`）
  1. 确认根子地图已设为默认（⭐）且两图点云均可见。
  2. 右键待对齐子地图 → **🔧 对齐 Transform (3D-BBS)**。
  3. 点 **在地图上选择点**，在**根子地图**点云上点一下给出粗位置；必要时调整搜索/裁剪参数，
     可先 **预览裁剪框**（青色=目标搜索区，黄色=源裁剪区）。
  4. **开始对齐** → 成功后视口**预览**新位姿 → **应用结果** 写入该子地图 `transform`。

- **方式三：手动指定 `transform`**（已知外参 / 微调 / 匹配失败时）
  在树中**选中**该子地图，右侧「属性编辑 → 变换 (Transform → default_submap)」直接填
  平移 `tx,ty,tz` 与四元数 `qx,qy,qz,qw`，点 **应用修改**（会自动归一化四元数）。

**建立父子关系**：右键该子地图 → **🔗 设置父地图** → 选择父节点（如 `floor`）。
这样它就挂到 TF 树上，`transform` 被解释为「本地 → 父」。
> 提示：如果所有子地图都直接挂在根下，`transform` 就是「本地 → 根（全局）」。
> 可随时右键根节点 → **🌳 显示 TF 树** 检查层级是否正确。

### 步骤 5：添加语义点位

对每个需要点位的子地图：

1. 在树中右键该子地图（或其「📍 语义点位」文件夹）→ **📍 添加语义点位**。
2. 右侧「属性编辑」进入新点位编辑：
   - 填 **名称**；
   - 点 **从点云选点**，然后在**该子地图的点云**上左键单击，把 `position` 填入（**子地图局部坐标**）；
   - 选择 **类型**（`single_pose` / `multi_pose` / `elevator_*` / `door_open` …）；
   - 需要时勾选 / 取消 **need_inspect**；
   - 调整 `orientation`（朝向四元数）。
3. 完成后点位以标记 + 朝向箭头显示在 3D 视图。
4. 需要移动：在 3D 视图中把鼠标移到该点标记上，**长按左键**拖拽（主要更新 `single_pose` 的首个位姿）。
5. 重命名：树中右键点位 → **✏️ 重命名**（会同步更新所有引用它的路线 waypoint）。

> `multi_pose` 用于“进/出方向”等需依次经过的多点场景。

### 步骤 6：添加传送门（两个方向都要建）

以 `floor ↔ underground` 的电梯口为例：

1. 在 `floor` 子地图上右键（或其「🚪 传送门」文件夹）→ **🚪 添加传送门**。
2. 在弹出的对话框中：
   - 选择 / 输入 **传送门点位名称**（对应一个语义点位，如 `电梯口`；不存在时会创建对应点位）；
   - 选择 **目标子地图** = `underground`。
3. **切换到 `underground` 子地图，重复**上述步骤，方向设为目标 = `floor`
   （因为传送门是**单向**的，双向通行需两边各建一条）。
4. 确保两边传送门关联的点位坐标都落在两图**物理重叠**的真实位置上。

### 步骤 7：创建路线（可选）

1. 在「SLAM地图」Tab 的「🛤️ 内部路线 (Routes)」根节点上右键 → **添加路线**，输入名称（如 `线路A`）。
2. **添加途经点**：从树中**拖动某个语义点**，释放到目标**路线节点**或路线下的某个途经点上，
   即在该位置插入一个 waypoint（引用「子地图 + 语义点名」）。跨子地图直接拖不同子地图下的点位即可。
3. **嵌套路线**：把一条路线拖到另一条路线上，可实现路线复用（生成 `{"route": ...}` 途经点）。
4. **默认路线**：右键路线 → **⭐ 设为默认路线**。
5. 勾选路线的「显示」列，可在 3D 视图看到按顺序连接的**彩色折线**（≥2 个有效途经点时可见）。

### 步骤 8：校验

- 右键根节点 → **🌳 显示 TF 树**：确认父子层级、根节点正确。
- 勾选各子地图点云与语义点/传送门显示，肉眼确认各图**相对位置、点位、传送门**都在真实位置。
- 显示路线折线，确认顺序合理、没有“飞线”（飞线通常意味着某子地图 `transform` 没对齐）。

### 步骤 9：保存 / 导出

有两种保存目标，含义不同：

- **保存为可继续编辑的“场景”**（含本地图、可能的其它地图/OSM/全局路线）：
  菜单 **文件 → 保存场景 (目录)** / **场景另存为 (目录)…**，选择目录，写出 `scene.json` 并复制点云。
  适合“做到一半下次接着编辑”。

- **导出为运行时可用的独立地图工程**（`<目录名>.json` + PCD，即 `multifloor.json` 风格）：
  切到「**场景地图**」Tab → 右键该 **SLAM 地图** → **📤 单独导出此地图…** → 选择/新建目标目录。
  这一步产出的目录即可交给 `NaviAgent/MapManager`（见 `submap_system.md`）加载使用。

保存前建议在 **文件 → 修改版本号** 里更新 `version`；`build_no` 会在保存时自动刷新。

> **保存前置条件**：必须存在且已设置有效的 **默认子地图（`default_submap`）**，否则会被提示阻止。

## 5. 场景地图制作流程（OSM + 多张 SLAM 地图）

当你需要把**多张 SLAM 地图**摆到真实地理位置、并做**跨地图导航**时，用「场景」把它们组织起来。
本章的操作主要在「**场景地图**」Tab 完成；单张地图的内部编辑仍回到「SLAM地图」Tab（§4）。

### 步骤 1：导入 OSM 底图

菜单 **文件 → 导入 OSM…** / **导入 OSM PBF…**，选择 `.osm` 或 `.osm.pbf`。
导入后自动切到「场景地图」Tab，中央 2D 总览渲染底图；场景原点默认取底图边界中心。

> 选中左侧树的 **OSM 底图**节点，右侧属性栏会显示底图经纬度范围（xmin/xmax/ymin/ymax）与当前鼠标位置经纬度。

### 步骤 2：加入 SLAM 地图

- **导入已有 SLAM 地图**：「场景地图」Tab 工具栏「导入SLAM地图」（或「SLAM地图」Tab 的「导入 SLAM 地图…」），
  选择一张已做好的地图目录（§4 的产物）。它会作为一张 SLAM 地图加入场景，正交投影足迹叠加到底图上。
- **另起炉灶新建空白 SLAM 地图**：「SLAM地图」Tab 工具栏「＋ 新增 SLAM 地图」，创建一张与现有地图无关的空白地图
  并设为激活，清空当前面板/主视图，从零开始搭建（子地图、点位等按 §4 操作）。

### 步骤 3：把 SLAM 地图对齐到 OSM 底图（geo_anchor）

在「场景地图」总览里，对每张 SLAM 地图的正交投影足迹：

- **左键拖拽** = 平移（改 `origin` 经纬度）；
- **右键拖拽 / Alt+左键** = 绕自身原点旋转（改 `heading_deg`）；
- **Shift+左键** = 缩放（改 `scale`）；
- 也可选中该地图后，在右侧属性栏**直接微调**经纬度与朝向。

对齐时的两个保护机制：

- **Ctrl+Z**：逐步撤销上一步拖拽结果，避免误操作破坏已对好的对齐。
- **🔒 锁定对齐结果**：在属性栏点击锁定后，该地图不能被单独拖动（拖它变成平移整个视图），编辑框只读；
  确认最终结果后建议锁定，需要再调时先解锁。

> 勾选每张 SLAM 地图的「显示」列可控制其正交投影是否叠加，便于逐张对齐。

### 步骤 4：场景语义点位与区域

在「场景地图」Tab 的「📍 语义点位」节点下管理直接标注在 OSM 底图上的点位（经纬度 + 航向角）：

1. **新建区域**：右键「📍 语义点位」→ 新建区域（如「智城」「彩虹」），用于分组聚合。
2. **新增点位**：工具栏「＋ 语义点位」或右键某区域 → 添加点位；随后在底图上**点选**位置，
   或在右侧属性栏精细调整经纬度、**航向角**、类型（默认 `single_pose`）、`need_inspect`（默认 `false`）、所属区域。
3. **管理**：右键点位可重命名 / 删除 / **移动到其它区域**；也可把点位**拖拽**到另一区域改归属。

> 提示：在底图上点选或应用属性修改时**不会**重置当前缩放/平移视图。

### 步骤 5：场景传送门

右键「🚪 传送门」节点 → 添加传送门：选择一个**场景语义点位**并指定它作为哪张 **SLAM 地图**的入口。
传送门以“语义点位 → 目标 SLAM 地图”显示，无需单独命名（与 SLAM 内部传送门一致）。

### 步骤 6：跨地图全局路线

在「🌐 全局路线」节点右键 → 添加全局路线，然后往里加途经点（异构，见 §1.12）：

- **拖入场景语义点位**：把某个「📍 语义点位」拖到某条全局路线（或其某个途经点）上，按落点位置插入。
- **拖入 SLAM 内部路线**：在「SLAM地图」Tab 里按住某条**内部路线**，把鼠标移到左侧「**场景地图**」标签上
  **悬停**（Tab 自动切换），再落到目标全局路线的指定位置，即把这条内部路线作为该全局路线的一段
  （`{"slam_map": ..., "route": ...}`）。
- 拖拽为 Copy 语义、按落点计算插入索引、拖完不收起列表，风格与 SLAM 内部路线拖拽一致。

### 步骤 7：重命名 / 单独导出 SLAM 地图

- **重命名**：右键某张 SLAM 地图 → 重命名，可分别修改**全名**与 **code**（节点名/唯一标识）；
  改 code 会自动同步全局路线途经点与场景传送门中的引用（见 §1.13）。
- **单独导出**：右键该 SLAM 地图 → **📤 单独导出此地图…**，导出为运行时可用的独立地图工程目录。

### 步骤 8：保存 / 打开场景（以目录为单位）

- **保存场景**：**文件 → 保存场景 (目录)** / **场景另存为 (目录)…**，选择目录；写出 `scene.json`，
  并把 OSM 与各 SLAM 地图的 PCD **复制进目录**，JSON 内一律用**相对路径**引用，便于整目录迁移。
- **打开场景**：**文件 → 打开场景目录…**，选择含 `scene.json` 的目录。
- 顶层 `scene.build_no` 与各 SLAM 地图的 `global.build_no` 都**仅在内容有更新时**才刷新时间戳（见 §1.14）。

## 6. 坐标系与变换详解

理解这一节能避免 90% 的“点位飘移 / 路线飞线”问题。

### 6.1 变换方向约定

每个子地图的 `transform` 定义 **本地坐标系 → 父坐标系** 的刚体变换（平移 + 四元数旋转）：

$$
P_{parent} = R \cdot P_{local} + T
$$

根子地图（`default_submap`）的父即全局，`transform` = 单位阵。

### 6.2 级联到全局

任意子地图局部点到全局坐标，沿 TF 树逐级向上相乘（即 `submapToRootMatrix`）：

$$
P_{global} = T_{parent\to root}\cdots T_{sub\to parent}\cdot P_{local}
$$

编辑器就是用它把语义点、传送门、路线折线画到 3D 世界里。

### 6.3 如何确定两图之间的 `transform`

- **首选**：用 3D-BBS 点云匹配自动求解（步骤 4 方式一/二）。
- **手工核对**：找到两图中**物理同一点**，读出它在两图各自局部坐标 `P_child`、`P_parent`，
  在纯平移（无旋转）情况下 `T = P_parent - P_child`。
  例：`floor` 中某点为 `(-50.2, -4.9, 0)`，同一点在 `underground` 为 `(-2.7, 3.5, 0)`，
  则 `underground.transform.translation ≈ (-47.5, -8.4, 0)`。

### 6.4 语义点坐标一律是“局部坐标”

添加语义点时“从点云选点”，落的是**该子地图的局部坐标**。因此**先对齐好 `transform`，再标点位**，
可以让 3D 里的世界位置一次到位；若先标点、后改 `transform`，点位的世界位置会随之整体移动（这是预期行为）。

## 7. 检查清单与常见问题

### 7.1 交付前检查清单

- [ ] 每个子地图都有唯一 `id` 与对应 `.pcd`（`map_file` 相对路径正确）。
- [ ] 已设置有效的 **默认子地图**（TF 树根，⭐）。
- [ ] 每个非根子地图都设置了 `parent_submap` 且 `transform` 已对齐。
- [ ] 关键语义点位齐全，类型与 `need_inspect` 正确。
- [ ] 需要互通的子地图之间，**两个方向**的传送门都已建立，且落在物理重叠处。
- [ ] 路线途经点顺序正确，折线无飞线；如需默认路线已设置。
- [ ] 已更新 `version`，并**导出独立地图工程目录**交付。

**做场景（多张 SLAM 地图）时额外检查：**

- [ ] 已导入 OSM 底图，场景原点合理。
- [ ] 每张 SLAM 地图的 `geo_anchor` 已对齐到底图真实位置；确认无误的已**锁定**。
- [ ] 每张 SLAM 地图有稳定的 **code(id)**；全局路线/传送门引用的 code 正确。
- [ ] 场景语义点位经纬度/航向角/区域正确；场景传送门指向的目标 SLAM 地图存在。
- [ ] 跨地图全局路线的途经点（场景点位 / 地图点位 / 内部路线段）顺序正确。
- [ ] 已用 **保存场景 (目录)** 保存，目录内含 `scene.json` + OSM + 各地图 PCD（相对路径引用）。

### 7.2 常见问题

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 无法保存 / 被提示 | 未设置有效 `default_submap` | 右键根子地图 → 设为默认地图 |
| 只能设某图为默认、别的不行 | 目标子地图有父节点 | 先右键**清除父节点**，或选真正的根 |
| 子地图点云错位 | `transform` 未对齐 | 用 3D-BBS 重新匹配，或手动填 `transform` |
| 语义点 / 路线在 3D 里飘 | 对应子地图 `transform` 不对 | 修正该子地图对齐关系 |
| 跨楼层导航切不过去 | 传送门只建了单向 | 在目标子地图补建反向传送门 |
| 路线折线不显示 | 有效途经点少于 2 个 / 未勾选显示 | 补途经点并勾选路线“显示” |
| 3D-BBS 对齐失败 | 搜索范围/裁剪/得分阈值不当，或初始点选偏 | 调参、缩小搜索范围、重选初始点（见 README §6） |
| 导入 PBF 后看不到底图 | 未切到「场景地图」Tab | 切到「场景地图」Tab 查看 2D 总览 |
| 场景里某张 SLAM 地图拖不动 | 该地图已**锁定** | 在属性栏点击解锁后再拖 |
| 拖对齐拖坏了 | 误操作 | 按 **Ctrl+Z** 逐步回退到上一步拖动结果 |
| 内部路线拖不进全局路线 | Tab 未切换 / 落点不是全局路线 | 悬停「场景地图」标签等其自动切换，再落到全局路线上 |
| 改了地图 code 后引用失效 | — | 编辑器会自动同步引用；如手改 JSON 需自行同步 `slam_map` 键 |
