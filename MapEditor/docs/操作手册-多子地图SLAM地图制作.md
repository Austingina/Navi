## 1. 先理解关键概念

在动手前，先建立下面这几个概念的心智模型，后续每一步都会用到。

### 1.1 地图工程（Map Project）与工程目录

一张完整的 SLAM 地图在 MapEditor 中对应一个 **地图工程（MapProject）**，以**文件夹**为读写单位：

- 主配置文件名 = **`<目录名>.json`**。例如目录 `maps/building_a/`，则配置为 `maps/building_a/building_a.json`。
- 各子地图的点云 `.pcd` 也存放在该目录下，`map_file` 用**相对路径**引用。
- `global.default_submap` 指定全局参考子地图；**未设置有效值时无法正常保存 / 被运行时正确加载**。

> 这个「目录 + 同名 JSON + 若干 PCD」的结构，正是运行时 `NaviAgent/MapManager` 读取的
> `multifloor.json` 风格地图（见 `submap_system.md` §2）。

### 1.2 子地图（Submap）

**子地图**是地图的最小可加载单元，通常对应一个楼层 / 一个区域 / 一次连续 SLAM 建图的结果。
一张地图由多个子地图组成，每个子地图有：

| 属性 | 含义 |
|------|------|
| `id` | 唯一标识（英文/数字，建议如 `floor`、`underground`、`5floor`） |
| `name` / `description` | 人类可读名称与描述 |
| `map_file` | 该子地图的点云文件（相对工程目录） |
| `transform` | 该子地图**本地坐标系 → 父子地图坐标系**的刚体变换 |
| `parent_submap` | 父子地图 id（为空表示它是 TF 树的**根**，即 `default_submap`） |
| `semantic_points` | 该子地图内的语义点位 |
| `submap_portals` | 从该子地图通往其它子地图的传送门 |

### 1.3 TF 树、`transform` 与 `default_submap`

多个子地图通过 **父子关系** 组成一棵 **TF 树**：

```
        floor  (根 = default_submap, transform = 单位阵)
        ├── underground   (parent_submap = floor)
        └── 5floor        (parent_submap = floor)
```

- 每个子地图的 `transform` 表示 **本地坐标 → 父坐标** 的变换。
- 根节点（`default_submap`）没有父节点，其 `transform` 为单位阵，它的坐标系即**全局坐标系**。
- 任意子地图局部点到全局的变换 = 沿 TF 树逐级向上级联（`submapToRootMatrix`）：

$$
T_{sub \to root} = T_{parent \to root}\cdot T_{sub \to parent}
$$

- **只有 TF 树的根节点才能被设为 `default_submap`**（编辑器会强制校验）。

> 为什么重要：语义点、传送门、路线折线在 3D 视图中的世界位置，都是用 `submapToRootMatrix`
> 把子地图局部坐标换算到全局后绘制的。对齐没做对，点位就会“飘”。

### 1.4 语义点位（Semantic Point）

**语义点位**是子地图内一个**命名的导航目标 / 关键位姿**，坐标是该子地图的**局部坐标**。

- 每个点位有 `type`（类型）与一个或多个位姿（position + orientation 四元数）。
- 支持的类型（编辑器右侧属性栏下拉可选）：
  `single_pose`、`multi_pose`、`LowPrecision_pose`、`elevator_call`、`elevator_wait`、
  `elevator_in`、`elevator_out`、`door_open`。
  - `single_pose`：单个目标位姿（最常用）。
  - `multi_pose`：一串**按顺序经过**的位姿（如出入口、闸机的“进/出方向”）。
  - `elevator_*` / `door_open`：电梯 / 门等特殊语义，供上层决策使用。
- `need_inspect`（是否需要巡检）：`single_pose` 默认 `true`，其它类型默认 `false`，可手动改。

### 1.5 传送门（Portal）

**传送门**是**两个子地图之间的连接点**，用于跨子地图（跨楼层）导航时“切图”。

- 传送门由 `portal`（一个**语义点位名**，即传送点的物理位置）+ `submap`（**目标子地图 id**）组成。
- **传送门是单向的**：`floor → underground` 与 `underground → floor` 需要**分别定义**。
- 实践上应把传送门设在两个子地图**物理重叠**的位置（电梯口、楼梯口、坡道口），
  且传送门关联的语义点位坐标要反映真实物理位置。

### 1.6 路线（Route）

**路线**是一串有序途经点（waypoint），可跨子地图：

- 每个 waypoint 引用 `{submap, semantic_point}`（某子地图里的某个语义点）。
- 也可**嵌套引用另一条路线**（`route` 字段），实现路线复用。
- `default_route` 指定默认路线。

### 1.7 版本号与构建号

- `version`：语义版本号，默认 `1.0`，由你在「文件 → 修改版本号」中手动维护。
- `build_no`：**每次保存**时自动写为 `YYYYMMDDHHMMSS`，供下游比对“是否有新版本”，无需手填。

### 1.8 场景层（可选，进阶）

MapEditor 还支持把多张 SLAM 地图用经纬度 `geo_anchor` 锚定到一张 **OSM 底图**上，组成“场景”。
本手册聚焦于**单张多子地图 SLAM 地图**的制作；场景 / OSM 对齐属于进阶主题，见 `README.md` §11.5。

## 2. 产物长什么样（目标 JSON 结构）

制作完成后，工程目录里的 `<目录名>.json` 结构如下（这也是运行时消费的格式）。
先看一眼目标，制作过程会更有方向感：

```json
{
  "global": {
    "default_submap": "floor",
    "default_route": "线路A",
    "version": "1.0",
    "build_no": 20260720101500
  },
  "submaps": {
    "floor": {
      "name": "地面层",
      "description": "Ground floor / 1F",
      "map_file": "floor.pcd",
      "transform": {
        "translation": {"x": 0.0, "y": 0.0, "z": 0.0},
        "rotation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0}
      },
      "submap_portals": [
        {"portal": "电梯口", "submap": "underground"}
      ],
      "semantic_points": {
        "北面车库": {
          "type": "single_pose",
          "pose": {
            "position": {"x": -50.2, "y": -4.9, "z": 0.0},
            "orientation": {"x": 0.0, "y": 0.0, "z": 0.7071, "w": 0.7071}
          },
          "need_inspect": true
        },
        "电梯口": {
          "type": "single_pose",
          "pose": { "position": {"x": -2.0, "y": 3.0, "z": 0.0},
                    "orientation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0} },
          "need_inspect": false
        }
      }
    },
    "underground": {
      "name": "地下层",
      "map_file": "underground.pcd",
      "parent_submap": "floor",
      "transform": {
        "translation": {"x": -47.5, "y": -8.4, "z": 0.0},
        "rotation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0}
      },
      "submap_portals": [
        {"portal": "电梯口", "submap": "floor"}
      ],
      "semantic_points": {
        "电梯口": { "type": "single_pose",
          "pose": { "position": {"x": 0.0, "y": 0.0, "z": 0.0},
                    "orientation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0} },
          "need_inspect": false }
      }
    }
  },
  "routes": {
    "线路A": {
      "description": "从地面层经地下层巡检",
      "waypoints": [
        {"submap": "floor", "semantic_point": "北面车库"},
        {"submap": "underground", "semantic_point": "电梯口"}
      ]
    }
  }
}
```

字段与概念的对应关系已在 §1 说明。`multi_pose` 类型的点位用 `poses`（数组）代替 `pose`；
嵌套路线的 waypoint 形如 `{"route": "线路A"}`。

## 3. 准备工作

1. **编译并启动 MapEditor**（详见 `README.md` §3）：

   ```bash
   cd /home/navi/Navi/MapEditor
   mkdir -p build && cd build
   cmake .. -DCMAKE_BUILD_TYPE=Release && make -j$(nproc)
   ./MapEditor
   ```

2. **准备各子地图的点云**：每个楼层 / 区域一份 `.pcd`（SLAM 建图输出）。

3. **界面速览**：
   - 左侧「**场景地图**」Tab：OSM 底图（可选）+ 各 SLAM 地图 + 全局路线。
   - 左侧「**SLAM地图**」Tab：**当前激活地图**的子地图树（子地图 / 地图点云 / 语义点位 / 传送门）+ 其内部路线。**本手册的编辑主要在此 Tab 完成。**
   - 中央 **3D 视图**：点云、坐标轴、语义点 / 传送门标记、路线折线。
   - 右侧「**属性编辑**」：当前选中子地图 / 语义点 / 传送门的属性。

## 4. 完整制作流程（分步）

下面以「制作一张含 `floor`（根）+ `underground` 两个子地图」的地图为例。三个及以上子地图同理扩展。

### 步骤 0：规划

先在纸面上确定：

- 各子地图 `id`（英文，稳定不改）与哪一张作**根 / 默认子地图**（`default_submap`，一般是主楼层）。
- 各子地图之间的**物理重叠点**（未来的传送门位置，如电梯口）。
- 需要的关键语义点位与巡检路线。

### 步骤 1：建立工程并载入第一张子地图（根）

编辑器需要一个**已激活的地图工程**作为编辑对象。选择下面任一种方式载入根子地图：

- **A. 已有地图目录**（推荐，若 SLAM 产物已是「目录 + `<目录名>.json`」结构）：
  菜单 **文件 → 导入单张地图目录 (multifloor.json)…**，选择该目录。它会成为当前激活地图。

- **B. 从零起步（仅有裸 `.pcd`）**：先做一次性“种子”目录 —— 新建文件夹（如 `building_a/`），
  把根子地图点云放进去（如 `floor.pcd`），并在其中放一个最小的 `building_a.json`：

  ```json
  {
    "global": { "default_submap": "floor" },
    "submaps": {
      "floor": {
        "name": "地面层",
        "map_file": "floor.pcd",
        "transform": { "translation": {"x":0.0,"y":0.0,"z":0.0},
                       "rotation": {"x":0.0,"y":0.0,"z":0.0,"w":1.0} },
        "submap_portals": [],
        "semantic_points": {}
      }
    },
    "routes": {}
  }
  ```

  然后同样用 **文件 → 导入单张地图目录** 打开它。此后所有编辑都在 GUI 完成。
  （若你的 SLAM 流程能直接产出上述结构，可跳过手写这步。）

载入后编辑器会自动切到「SLAM地图」Tab，3D 视图显示根子地图点云。

### 步骤 2：确认默认子地图（根节点）

在「SLAM地图」Tab 的子地图树中，右键根子地图（如 `floor`）→ **⭐ 设为默认地图**（即 `default_submap`）。
名称旁出现 ⭐ 即表示它是 `default_submap` / TF 树根，`transform` 保持单位阵。

> 只有**无父节点**的子地图才能设为默认子地图。

### 步骤 3：加入其余子地图

对每一个附加子地图（如 `underground`）：

1. 菜单 **编辑 → 新增 Submap…**（或工具栏 `+ Submap`、面板 `+ 新增 Submap`）。
2. 在对话框中填写 **id**（如 `underground`）、名称、描述，并**导入其 `.pcd`**（可选同时导入其 JSON）。
3. 确定后，该子地图出现在树中，点云叠加显示在 3D 视图（初始 `transform` 为单位阵，通常会与根图重叠/错位，下一步对齐）。

### 步骤 4：把子地图对齐到根坐标系，并建立父子关系

目的：让每个子地图的点云在**同一个全局坐标系**里对上真实相对位置，并写入其 `transform`。

有三种方式（详细参数见 `README.md` §6），按数据情况任选：

- **方式一 / 二：3D-BBS 点云匹配**（推荐，自动求解 `transform`）
  1. 确认根子地图已设为默认（⭐）且两图点云均可见。
  2. 右键待对齐子地图 → **🔧 对齐 Transform (3D-BBS)**。
  3. 点 **在地图上选择点**，在**根子地图**点云上点一下给出粗位置；必要时调整搜索/裁剪参数，
     可先 **预览裁剪框**（青色=目标搜索区，黄色=源裁剪区）。
  4. **开始对齐** → 成功后视口**预览**新位姿 → **应用结果** 写入该子地图 `transform`。

- **方式三：手动指定 `transform`**（已知外参 / 微调 / 匹配失败时）
  在树中**选中**该子地图，右侧「属性编辑 → 变换 (Transform → default_submap)」直接填
  平移 `tx,ty,tz` 与四元数 `qx,qy,qz,qw`，点 **应用修改**（会自动归一化四元数）。

**建立父子关系**：右键该子地图 → **🔗 设置父地图** → 选择父节点（如 `floor`）。
这样它就挂到 TF 树上，`transform` 被解释为「本地 → 父」。
> 提示：如果所有子地图都直接挂在根下，`transform` 就是「本地 → 根（全局）」。
> 可随时右键根节点 → **🌳 显示 TF 树** 检查层级是否正确。

### 步骤 5：添加语义点位

对每个需要点位的子地图：

1. 在树中右键该子地图（或其「📍 语义点位」文件夹）→ **📍 添加语义点位**。
2. 右侧「属性编辑」进入新点位编辑：
   - 填 **名称**；
   - 点 **从点云选点**，然后在**该子地图的点云**上左键单击，把 `position` 填入（**子地图局部坐标**）；
   - 选择 **类型**（`single_pose` / `multi_pose` / `elevator_*` / `door_open` …）；
   - 需要时勾选 / 取消 **need_inspect**；
   - 调整 `orientation`（朝向四元数）。
3. 完成后点位以标记 + 朝向箭头显示在 3D 视图。
4. 需要移动：在 3D 视图中把鼠标移到该点标记上，**长按左键**拖拽（主要更新 `single_pose` 的首个位姿）。
5. 重命名：树中右键点位 → **✏️ 重命名**（会同步更新所有引用它的路线 waypoint）。

> `multi_pose` 用于“进/出方向”等需依次经过的多点场景。

### 步骤 6：添加传送门（两个方向都要建）

以 `floor ↔ underground` 的电梯口为例：

1. 在 `floor` 子地图上右键（或其「🚪 传送门」文件夹）→ **🚪 添加传送门**。
2. 在弹出的对话框中：
   - 选择 / 输入 **传送门点位名称**（对应一个语义点位，如 `电梯口`；不存在时会创建对应点位）；
   - 选择 **目标子地图** = `underground`。
3. **切换到 `underground` 子地图，重复**上述步骤，方向设为目标 = `floor`
   （因为传送门是**单向**的，双向通行需两边各建一条）。
4. 确保两边传送门关联的点位坐标都落在两图**物理重叠**的真实位置上。

### 步骤 7：创建路线（可选）

1. 在「SLAM地图」Tab 的「🛤️ 内部路线 (Routes)」根节点上右键 → **添加路线**，输入名称（如 `线路A`）。
2. **添加途经点**：从树中**拖动某个语义点**，释放到目标**路线节点**或路线下的某个途经点上，
   即在该位置插入一个 waypoint（引用「子地图 + 语义点名」）。跨子地图直接拖不同子地图下的点位即可。
3. **嵌套路线**：把一条路线拖到另一条路线上，可实现路线复用（生成 `{"route": ...}` 途经点）。
4. **默认路线**：右键路线 → **⭐ 设为默认路线**。
5. 勾选路线的「显示」列，可在 3D 视图看到按顺序连接的**彩色折线**（≥2 个有效途经点时可见）。

### 步骤 8：校验

- 右键根节点 → **🌳 显示 TF 树**：确认父子层级、根节点正确。
- 勾选各子地图点云与语义点/传送门显示，肉眼确认各图**相对位置、点位、传送门**都在真实位置。
- 显示路线折线，确认顺序合理、没有“飞线”（飞线通常意味着某子地图 `transform` 没对齐）。

### 步骤 9：保存 / 导出

有两种保存目标，含义不同：

- **保存为可继续编辑的“场景”**（含本地图、可能的其它地图/OSM/全局路线）：
  菜单 **文件 → 保存场景 (目录)** / **场景另存为 (目录)…**，选择目录，写出 `scene.json` 并复制点云。
  适合“做到一半下次接着编辑”。

- **导出为运行时可用的独立地图工程**（`<目录名>.json` + PCD，即 `multifloor.json` 风格）：
  切到「**场景地图**」Tab → 右键该 **SLAM 地图** → **📤 单独导出此地图…** → 选择/新建目标目录。
  这一步产出的目录即可交给 `NaviAgent/MapManager`（见 `submap_system.md`）加载使用。

保存前建议在 **文件 → 修改版本号** 里更新 `version`；`build_no` 会在保存时自动刷新。

> **保存前置条件**：必须存在且已设置有效的 **默认子地图（`default_submap`）**，否则会被提示阻止。

## 5. 坐标系与变换详解

理解这一节能避免 90% 的“点位飘移 / 路线飞线”问题。

### 5.1 变换方向约定

每个子地图的 `transform` 定义 **本地坐标系 → 父坐标系** 的刚体变换（平移 + 四元数旋转）：

$$
P_{parent} = R \cdot P_{local} + T
$$

根子地图（`default_submap`）的父即全局，`transform` = 单位阵。

### 5.2 级联到全局

任意子地图局部点到全局坐标，沿 TF 树逐级向上相乘（即 `submapToRootMatrix`）：

$$
P_{global} = T_{parent\to root}\cdots T_{sub\to parent}\cdot P_{local}
$$

编辑器就是用它把语义点、传送门、路线折线画到 3D 世界里。

### 5.3 如何确定两图之间的 `transform`

- **首选**：用 3D-BBS 点云匹配自动求解（步骤 4 方式一/二）。
- **手工核对**：找到两图中**物理同一点**，读出它在两图各自局部坐标 `P_child`、`P_parent`，
  在纯平移（无旋转）情况下 `T = P_parent - P_child`。
  例：`floor` 中某点为 `(-50.2, -4.9, 0)`，同一点在 `underground` 为 `(-2.7, 3.5, 0)`，
  则 `underground.transform.translation ≈ (-47.5, -8.4, 0)`。

### 5.4 语义点坐标一律是“局部坐标”

添加语义点时“从点云选点”，落的是**该子地图的局部坐标**。因此**先对齐好 `transform`，再标点位**，
可以让 3D 里的世界位置一次到位；若先标点、后改 `transform`，点位的世界位置会随之整体移动（这是预期行为）。

## 6. 检查清单与常见问题

### 6.1 交付前检查清单

- [ ] 每个子地图都有唯一 `id` 与对应 `.pcd`（`map_file` 相对路径正确）。
- [ ] 已设置有效的 **默认子地图**（TF 树根，⭐）。
- [ ] 每个非根子地图都设置了 `parent_submap` 且 `transform` 已对齐。
- [ ] 关键语义点位齐全，类型与 `need_inspect` 正确。
- [ ] 需要互通的子地图之间，**两个方向**的传送门都已建立，且落在物理重叠处。
- [ ] 路线途经点顺序正确，折线无飞线；如需默认路线已设置。
- [ ] 已更新 `version`，并**导出独立地图工程目录**交付。

### 6.2 常见问题

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 无法保存 / 被提示 | 未设置有效 `default_submap` | 右键根子地图 → 设为默认地图 |
| 只能设某图为默认、别的不行 | 目标子地图有父节点 | 先右键**清除父节点**，或选真正的根 |
| 子地图点云错位 | `transform` 未对齐 | 用 3D-BBS 重新匹配，或手动填 `transform` |
| 语义点 / 路线在 3D 里飘 | 对应子地图 `transform` 不对 | 修正该子地图对齐关系 |
| 跨楼层导航切不过去 | 传送门只建了单向 | 在目标子地图补建反向传送门 |
| 路线折线不显示 | 有效途经点少于 2 个 / 未勾选显示 | 补途经点并勾选路线“显示” |
| 3D-BBS 对齐失败 | 搜索范围/裁剪/得分阈值不当，或初始点选偏 | 调参、缩小搜索范围、重选初始点（见 README §6） |
