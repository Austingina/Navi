# 多雷达外参标定历史

`lidar_extrinsics.yaml` 只保留当前生效的一组值。每次重标前把旧的一组连同当时的机械
安装状态归档到这里 —— 光有数字没有安装状态，事后无法判断某组值为什么不同。

标定方法与验收判据见 `../README.md`「坑 5b」与 `../scripts/calib_extrinsic.py`。

---

## #1 — 2026-08-20（已作废）

引入 commit `97a335e9 add the front and back lidar merger`。

**当时的机械安装**：前后雷达朝向基本一致（两台 MID360 水平 FOV 都是 360° 全向，
「前/后」只指安装位置）；前雷达向车头前倾 15°，后雷达 −15°。

**标定值**（back → front，`xyz_rpy`，平移 m / 旋转 rad）：

```
[-0.28563, 0.44809, -0.10994, -0.524487, 0.019861, -0.017750]
即 t = [-0.286, +0.448, -0.110] m,  rpy = [-30.05, +1.14, -1.02] 度
```

**质量指标**（点到面 GICP，车辆静止，结构丰富室内）：

| 指标 | 实测 | 阈值 |
|---|---|---|
| 共视区点到面残差 median | 0.0114 m（换一批数据交叉验证 0.0176 m） | < 0.03 |
| 有符号残差均值 | −0.0009 m | \|·\| < 0.01 |
| 共视比例（<0.2 m） | 90.0% | > 70% |
| 收敛一致性 | 3/3 个不同初值收敛到同一解 | — |

`roll = −30.05°` 几乎正好是整数，与「前 +15°、后 −15°」的机械设计吻合。
`yaw ≈ −1°` 说明两台雷达朝向一致，驱动配置里那个 `yaw: 180.0` 是死代码兼语义标记，
不是物理朝向。

**作废原因**：2026-08-28 双雷达重新安装 —— 前雷达移到车辆右前方，后雷达移到左后方。
外参以前雷达为参考系，两台都动了，这组值不再成立。同日
`outdoor_localization.launch.py` 的 `body->base_link` 也随之更新（前雷达改为前 0.28 m、
右 0.24 m、绕 Z 顺时针 90°、前倾 15°）。

## #2 — 2026-08-28（已作废）

标定方法上的新增结论见 `../README.md` 坑 5b。
原始点云：`~/lidar_calib_data/2026-08-28_pos1.npz`（33 MB，不入 git）。

**标定值**（back → front，`xyz_rpy`，平移 m / 旋转 rad）：

```
[-0.47108, -0.53500, -0.15476, 0.519963, -0.002289, -0.006167]
即 t = [-0.471, -0.535, -0.155] m,  rpy = [+29.79, -0.13, -0.35] 度
```

**质量指标**：

| 指标 | 实测 | 阈值 |
|---|---|---|
| 共视区点到面残差 median | 0.0133 m | < 0.03 |
| 有符号残差均值 | +0.0004 m | \|·\| < 0.01 |
| 共视比例（<0.2 m） | 77.5% | > 70% |
| 收敛一致性 | 2/3 个不同初值收敛到同一解 | — |

**当时的机械安装**（标定数据反推，非目测）：

| 雷达 | base_link 位置 | base_link 姿态 |
|---|---|---|
| front | 前 0.28 m、右 0.24 m | yaw −90.00°、倾角 −15.00°（launch 声明值，作基准） |
| back | 后 0.277 m、左 0.231 m | yaw −90.31°、倾角 +14.79° |

两台雷达 **yaw 同向**（相差 0.31°），倾角等大反向、各 15°；安装位置近乎中心对称。
装配前一度以为后雷达 yaw 是反向转的，实测否定，判决性实验记在 README 坑 5b。

前雷达自身系实测地面法向 `[+0.0063, -0.2855, +0.9584]`，与
`outdoor_localization.launch.py` 声明的（pitch −15°、roll 0）夹角仅 1.63°。
绝对倾角读数 front 16.59° / back 13.22°，均值 14.9° —— 两边各偏 ±1.7°，
应是标定时车停的地面有约 1.7° 坡，而非装配误差。

**作废原因**：2026-08-28 之后两台雷达又被**镜像重装** —— 前雷达 右前→左前、
后雷达 左后→右后。判决性证据见 #3。作废时 `outdoor_localization.launch.py` 的
前雷达安装量已被同步改成"左前 Rz+90"（未提交），但 `lidar_extrinsics.yaml` 里仍留着
本组（属于旧的"右前"安装）的值 —— 这两者搭配物理上不成立，是 #3 要修的状态。

## #3 — 2026-09-01（当前生效）

数值与质量指标见 `lidar_extrinsics.yaml` 的 `back` 段。
原始点云：`~/lidar_calib_data/2026-09-01_pos1.npz`（不入 git）；
ghosting 目视复核：`~/lidar_calib_data/2026-09-01_ghosting_check.png`。

**当时的机械安装**（标定数据反推，非目测）：

| 雷达 | base_link 位置 | base_link 姿态 |
|---|---|---|
| front | 前 0.275 m、左 0.225 m | yaw +90.00°、倾角 −15.00°（launch 声明值，作基准） |
| back | 后 0.283 m、右 0.204 m | yaw +89.74°、倾角 +15.42° |

相对 #2 是**整体镜像**：两台雷达各自换到车身另一侧，`roll` 与 `y` 因此都变号。
两台雷达仍 **yaw 同向**（相差 0.26°），倾角等大反向、各约 15°，
中心对称残差 2.1 cm。

**这不是符号笔误 —— 判决性证据。** 用 `calib_extrinsic.py --load-clouds` 在
两批点云上交叉评估同样的三组外参（可随时复现）：

| 外参 | @ 08-28 数据 | @ 09-01 数据 |
|---|---|---|
| #1 (08-20) | 0.1032 m / 共视 4.3% ✗ | 0.0562 m / 共视 71.4% ✗ |
| #2 (08-28) | **0.0133 m / 77.5% ✓** | 0.1084 m / 共视 7.4% ✗ |
| #3 (09-01) | 0.0883 m / 共视 6.5% ✗ | **0.0119 m / 74.9% ✓** |

每组值只拟合自己那批数据，且都只在**一种**前雷达安装约定下反推出物理上说得通的
布局（#2 → 右前，#3 → 左前）。若只是 yaml 抄错符号，不会有这种数据层面的分裂。

**遗留项**：室内栈 `odometry_lslidar.launch.py` 的 `imu_link->base_link`
仍是旧的"右前 Rz−90"（`imu_base_yaw=+1.5708`、平移 `-0.24, -0.270459, -0.072469`），
**未随镜像重装同步**，与室外栈现在不一致（README 与 CLAUDE.md 都要求两栈取值一致）。
本次标定只能测 back→front，无法测定 front→base_link，故未擅自改动室内栈。
